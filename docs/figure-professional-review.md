# 顶刊专业度评审：当前产出与一手论文图的差距

评审对象：`artifacts/onnx/journal/` 下三张真实模型图（Nature 栏宽、扁平模式）。
对照物：仓库内 `tmp/refs`、`tmp/pdfs` 的六张一手论文图。
可视化对照板：`artifacts/review/review-board.html`。

本文只回答一个问题：**这些图现在能不能投出去；不能的话，差在哪一步。**

---

## 一、结论

**字号已经合规，版式还没有。** 上一轮把字号锁进期刊 pt 区间是必要的，但它只解决了「印出来看不看得清」。审稿人第一眼判断的是**结构读不读得出来**——而当前三张图都读不出来：

| 图 | 版式方向 | 实际可读性 |
|---|---|---|
| U-Net | 对（左降右升的 U） | 步骤角标在上升臂**完全反序**，与箭头矛盾 |
| ResNet | 有列 | 没有「塔」的收窄感，残差分支无专属视觉语言 |
| ViT | 有列 | 看不出「同一块重复 L 次」，注意力结构不可读 |

## 二、致命问题（图不能用的原因）

### 2.1 步骤角标编号与数据流方向矛盾（已定位到代码）

`scene-svg-renderer.mjs:211-216`：

```js
// 阅读顺序：折行布局是列优先的，所以先按 x 再按 y 排序，正好等于数据流的先后。
const steps = new Map(
  [...bodies]
    .sort((left, right) => left.bounds.x - right.bounds.x || left.bounds.y - right.bounds.y)
    .map((primitive, index) => [String(primitive.id), index + 1]),
);
```

注释里的断言「先 x 后 y 正好等于数据流的先后」**只对自上而下的列成立**。U-Net 的 decoder 是上升臂：列内节点自下而上是 `Resize_8 → Concat_9 → … → Conv_15`，而角标自上而下编成 `9 → 16`。

实测（`unet-lite.visio-plan.json`）：

| 盒内算子 | 节点名 | y | 角标 |
|---|---|---|---|
| Conv（输出层，2 类） | `Conv_15` | 34（最上） | **9** |
| Resize（首个上采样） | `Resize_8` | 822（最下） | **16** |

读者会按角标读成「先 Conv 后 Resize」，与箭头方向相反。**编号在这里不是装饰，是错误信息。**

### 2.2 文字溢出形状

渲染器有字号下限保护（`labelMin`），所以长名字会缩小 + 折行；但折行后的高度没有回写到盒内排版，结果是溢出盒外。按渲染器同一套宽度估算口径实测：

| 模型 | 标签 | 需要宽 | 可用宽 | 越界 |
|---|---|---|---|---|
| resnet | `GlobalAveragePool` | 124 | 50（梯形中腰） | **2.5×** |
| unet | `Concat` | 66–74 | 20（⊕ 圆直径 34） | **3.7×** |
| vit | `LayerNormalization` | 84 | 58 | 1.44× |

三处都是**顶刊里的常规算子名**，不是边缘案例。根因是盒尺寸由张量形状决定（`data.tensorShape`），而文字排版没有反向约束盒尺寸，也没有「放不下就换位置」的退路。

### 2.3 连线穿过盒子

ViT 最严重：`MatMul(2)` 的支路绕行时压过 `Transpose` 盒与 `MatMul(10)` 盒；`Add(8) → Add(13)` 的水平线横穿整幅图。当前布线是「避开同列盒子」的局部规则，没有全局走廊分配。

## 三、严重问题（读起来不像顶刊）

1. **每盒挂 `encoder` / `decoder` / `conv` 小字**。顶刊是每段一条浅色背景带 + 一个段标签（ResNet 的 `conv2_x`…`conv5_x`、U-Net 的「contracting path / expansive path」）。逐盒重复把段信息降级成了噪声。
2. **每盒一个数字角标**。顶刊只在正文引用步骤时才编号。当前 16 个盒子 16 个角标，噪声压过信息。
3. **残差 / 跳跃连接没有专属视觉语言**。同一根线在 `main-flow` / `bypass` / `cross-scale` 之间只靠颜色和虚实区分，且残差分支与主分支同宽。顶刊会用显著不同的走线（绕行弧 + ⊕ 或直接标注 `identity`）。
4. **重复块未折叠**。Transformer 的核心是「同一块重复 L 次」；一手参考只画一次标 `×N`，我们把 4 个 `MatMul` 全铺开，反而看不出重复结构。
5. **列高不齐、右下大面积留白**。resnet 第 1 列到 y=590、第 4 列到 y=440，右侧近三分之一空白。没有列密度均衡。
6. **图内标题是文件名**（`unet-lite`）。顶刊标题在图注里，图内不该有标题。
7. **图例是中文**。顶刊正文用英文；中文还会引入字体嵌入问题（转曲或嵌入失败时印出方块）。

## 四、合规硬指标（逐条实测）

| 检查项 | 结果 | 实测 |
|---|---|---|
| 字号落在期刊 pt 区间 | 通过 | 6 张全部 5–7 pt，跨度精确 2.00 pt |
| 字体为 Helvetica / Arial | 通过 | `font-family: Helvetica,Arial,…` |
| 文字保持矢量 | 通过 | 全部 `<text>`，无 `<image>` 位图 |
| 无网格线 / 图案 | 通过 | 模块内装饰线已清零 |
| **线宽落在期刊 pt 区间** | ~~不通过~~ → **通过** | 已由 `unitsPerPt` 反推。6 张全部 **0.50 / 1.00 pt**（Cell 要求 0.5–1.5 pt）。修复前是 unet 0.49–0.89、resnet 0.65–1.17、vit 0.97–1.75 |
| **配色收敛 Okabe-Ito** | 不通过 | `BLOCK_STYLES`(12) / `styleForForm`(7) / `ROLE_STYLES` 三套并行；灰度打印可区分性从未验证 |
| **面板标签 (a)(b)** | 不通过 | 多面板图完全未支持 |

线宽那一条是纯工程遗漏：`STROKE = 1.25` 是 viewBox 单位常量，图幅一变小线就跟着变细。**它和字号是同一个问题，上一轮只修了一半。**

## 五、建议的推进顺序

按「投入产出比 × 阻塞程度」排序。

### P0 —— 让图从「错误」变成「不漂亮」

| # | 任务 | 为什么必须先做 |
|---|---|---|
| P0-1 | **步骤角标改为按数据流编号**（拓扑序），并支持关闭 | 当前编号是错误信息，会误导读者 |

## 七、仍然没做

**P0 只解决"错误"，没解决"不像顶刊"。** 下面这些一个都没动：

- **段带取代逐盒 badge**：现在每个盒子还挂着 `encoder` / `decoder` / `conv` 小字。顶刊是每段一条浅色背景带 + 一个段标签。
- **逐盒数字角标**：编号方向已经正确，但"每盒一个数字"本身仍是噪声。顶刊只在正文引用步骤时才编号。
- **连线走廊分配**：ViT 的 `Add(8) → Add(13)` 仍然横穿整幅图，`MatMul(2)` 的支路仍压过其他盒子。
- **重复块折叠 + `×N`**：Transformer 的"同一块重复 L 次"仍铺开成 4 个 `MatMul`，读不出重复结构。
- **列密度均衡**：右下方仍有大片留白。
- **图内标题是文件名**（`unet-lite`）；**图例是中文**（顶刊正文用英文，且中文会引入字体嵌入风险）。
- **配色未收敛 Okabe-Ito**；**面板标签 (a)(b) 未支持**；**张量尺寸标注仍是 ASCII `x` 且与盒内算子名重复**。
- `cnn-tower` 无真实样本；`lstm/gcn/gan/graphcast` 仍是 sequential 兜底；Visio 侧未同步。

## 八、一句话

**字号和线宽是「印出来能不能看清」，版式是「一眼能不能读懂」。** 前者两条都已收口；后者只把"错误信息"（角标反序）和"物理越界"（溢出、线宽）清掉了，**观感改造一步都还没做**。
