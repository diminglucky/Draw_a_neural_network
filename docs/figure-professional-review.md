## 一、结论

**字号已经合规，版式还没有。** 上一轮把字号锁进期刊 pt 区间是必要的，但它只解决了「印出来看不看得清」。审稿人第一眼判断的是**结构读不读得出来**——而当前三张图都读不出来：

| 图 | 版式方向 | 实际可读性 |
|---|---|---|
| U-Net | 对（左降右升的 U） | 步骤角标在上升臂**完全反序**，与箭头矛盾 |
| ResNet | 有列 | 没有「塔」的收窄感，残差分支无专属视觉语言 |
| ViT | 有列 | 看不出「同一块重复 L 次」，注意力结构不可读 |

## 二、致命问题（图不能用的原因）

### 2.1 步骤角标编号与数据流方向矛盾（已定位到代码）

`scene-svg-renderer.mjs:211-216`：

```js
// 阅读顺序：折行布局是列优先的，所以先按 x 再按 y 排序，正好等于数据流的先后。
const steps = new Map(
  [...bodies]
    .sort((left, right) => left.bounds.x - right.bounds.x || left.bounds.y - right.bounds.y)
    .map((primitive, index) => [String(primitive.id), index + 1]),
);
```

注释里的断言「先 x 后 y 正好等于数据流的先后」**只对自上而下的列成立**。U-Net 的 decoder 是上升臂：列内节点自下而上是 `Resize_8 → Concat_9 → … → Conv_15`，而角标自上而下编成 `9 → 16`。

实测（`unet-lite.visio-plan.json`）：

| 盒内算子 | 节点名 | y | 角标 |
|---|---|---|---|
| Conv（输出层，2 类） | `Conv_15` | 34（最上） | **9** |
| Resize（首个上采样） | `Resize_8` | 822（最下） | **16** |

读者会按角标读成「先 Conv 后 Resize」，与箭头方向相反。**编号在这里不是装饰，是错误信息。**

### 2.2 文字溢出形状

渲染器有字号下限保护（`labelMin`），所以长名字会缩小 + 折行；但折行后的高度没有回写到盒内排版，结果是溢出盒外。按渲染器同一套宽度估算口径实测：

| 模型 | 标签 | 需要宽 | 可用宽 | 越界 |
|---|---|---|---|---|
| resnet | `GlobalAveragePool` | 124 | 50（梯形中腰） | **2.5×** |
| unet | `Concat` | 66–74 | 20（⊕ 圆直径 34） | **3.7×** |
| vit | `LayerNormalization` | 84 | 58 | 1.44× |

三处都是**顶刊里的常规算子名**，不是边缘案例。根因是盒尺寸由张量形状决定（`data.tensorShape`），而文字排版没有反向约束盒尺寸，也没有「放不下就换位置」的退路。

### 2.3 连线穿过盒子

ViT 最严重：`MatMul(2)` 的支路绕行时压过 `Transpose` 盒与 `MatMul(10)` 盒；`Add(8) → Add(13)` 的水平线横穿整幅图。当前布线是「避开同列盒子」的局部规则，没有全局走廊分配。

## 三、严重问题（读起来不像顶刊）

1. **每盒挂 `encoder` / `decoder` / `conv` 小字**。顶刊是每段一条浅色背景带 + 一个段标签（ResNet 的 `conv2_x`…`conv5_x`、U-Net 的「contracting path / expansive path」）。逐盒重复把段信息降级成了噪声。
2. **每盒一个数字角标**。顶刊只在正文引用步骤时才编号。当前 16 个盒子 16 个角标，噪声压过信息。
3. **残差 / 跳跃连接没有专属视觉语言**。同一根线在 `main-flow` / `bypass` / `cross-scale` 之间只靠颜色和虚实区分，且残差分支与主分支同宽。顶刊会用显著不同的走线（绕行弧 + ⊕ 或直接标注 `identity`）。
4. **重复块未折叠**。Transformer 的核心是「同一块重复 L 次」；一手参考只画一次标 `×N`，我们把 4 个 `MatMul` 全铺开，反而看不出重复结构。
5. **列高不齐、右下大面积留白**。resnet 第 1 列到 y=590、第 4 列到 y=440，右侧近三分之一空白。没有列密度均衡。
6. **图内标题是文件名**（`unet-lite`）。顶刊标题在图注里，图内不该有标题。
7. **图例是中文**。顶刊正文用英文；中文还会引入字体嵌入问题（转曲或嵌入失败时印出方块）。

## 七、P1 第一批已完成（2026-10-13 续）

这一批的主题是「把视觉印象变成几何量测」——先造一把尺，再按尺改。

### 7.1 新增独立核验器：`scripts/check-figure-geometry.mjs`

字号和线宽有 `check-typography.mjs` 管，**排版位置一直没人管**。之前几处"看起来压住了"全靠肉眼，而肉眼在低分辨率光栅图上会骗人（P0 阶段已经吃过一次亏）。这个核验器直接解析成品 SVG 的 `<text>` / `<rect>` / `<polygon>` / `<path>`，把文字按同一套字宽模型还原成矩形，再做四类求交：

| 判据 | 说明 |
|---|---|
| `text-out-of-canvas` | 文字跑出画布 |
| `text-over-foreign-box` | 压住别的盒子（自己的盒子不算） |
| `text-outside-shape` | 从梯形斜腰里伸出去（梯形按**多边形**判，不用外接矩形——用外接矩形会把这唯一一类斜边溢出整个漏掉） |
| `text-over-connector` | 被连接线穿过（线段按 1 单位半宽算实体，零宽线段会把"线从正中穿过"判成不交） |
| `text-over-text` | 两处文字互相压住 |

三个容易写错、写错了就全是假警报的地方，都在代码里留了注释：连接线画在盒子之前，**盒内的线段是被遮住的**，必须先按盒子做线段减法；`.body-label` / `.block-badge` 用 `dominant-baseline:middle`，**y 是文字中心不是基线**；大写字母没有降部，"CONV" 不该被算到基线以下。

**适用范围（写在核验器的输出里，不藏着）**：只对**扁平模式**出判定。3D 模式下一个盒子由多张平面叠成，SVG 里只有最前面那张带类名，被它遮住的平面与连接线无法从成品还原——这类文件标 `(3D·仅供参考)`，结果不计入失败。宁可说"这条我量不了"，也不要拿一个量不准的数去冒充合规。

**首次运行的结果：三张扁平图共 34 处几何冲突**（32 处 `text-over-connector`、2 处 `text-over-text`）。全部是肉眼看得见但说不清量级的问题。

### 7.3 段名 badge 改成整图统一

按盒子逐个决定"画不画段名"，结果是 **ResNet 第一列只有前 3 个盒子带 `ENCODER`**——读者会以为那几个盒子有特殊含义，比一个都不画更糟。

规则改为**整图统一**：段带已经表达过分段语义时（`bands.length > 0`），或**任何一个**盒子装不下「名字 + 段名 + 序号圆」时，整张图都不画段名。判定函数 `bodyBadgeFits` 与逐盒排版共用同一份几何，不会各自漂移。

代价是这三张图的逐盒段名全部消失——它们本来就是重复信息（一列里每个盒子都写 `ENCODER`）。段名在"盒子大、块种类混合"的图上仍然会画。

## 八、VGG16 实测（2026-10-13 续）

被问"你会绘制 VGG16 这种的吗"。为了不空口回答，往 `tools/make-sample-onnx.mjs` 里加了一个**真实的 VGG16**：13 个卷积 + 3 个全连接 = 37 个算子，五段卷积塔（224→112→56→28→14→7），每段尾一个池化，末尾 25088→4096→4096→1000。**结论：结构画得出来，"像不像"分三层说。**

### 8.1 已经对的（不是这次改的，是之前就对）

对照 `tmp/pdfs/official-vgg16-1.png`（一手参考图），顶刊 VGG16 的视觉语言里这几条**已经成立**：

| 语言 | 实测 |
|---|---|
| 片高 ∝ 空间尺寸 | 盒高 96 / 60 / 42 / 33 / 28，正是 `24 + 边长×0.32`（`scaleSizeByTensorShape`） |
| 片宽 ∝ 通道数 | 56→64，方向对，但幅度只有 14% |
| 池化 = 收窄的梯形 | `wedge` 形态，语义由形状承载 |
| 全连接 = 细长条 | `stack` 形态 + 绿色 |
| 形状标注 | `512×28×28` 挂在盒下，与盒内算子名不重复 |

也就是说"越往后越窄"这条塔形**本来就有**——我一开始误以为是布局巧合，量过才确认是设计好的。

### 8.2 本轮改的：片数从常量变成随通道数

`featureMapStackGeometry` 里写死 `const N = 3`，于是 **64 通道和 512 通道画出来一模一样**，读者看不出 conv1 和 conv4 的区别，"深度"这个维度整个丢了。

改为按 `log2(通道数)` 压到 3–8 片：64→3、128→4、256→5、512→6。偏移步长同时受两条约束——常规尺寸下"看得出是摞的"（1.6–5），且最前面那片平面（也就是文字面）不能矮到放不下字（`STACK_PLANE_FLOOR = 22`）。渲染形状与计算文字面共用同一个 `featureMapDepthOf(primitive)`，两处不会漂移。

局部放大对比（512 通道同一处）：**一块厚砖 → 一摞六片**。

### 8.3 试过但撤掉的：扁平模式的盒内竖线

扁平模式没有等距投影，我一度给 `renderFlatVolume` 加了左侧几条竖线来暗示片数。**被既有契约拦下并撤掉**——项目里有一条测试明确锁着"模块内部不画装饰线，算子类型由「形状 + 标签 + 填充」承担"，理由是早期用"盒内 3×3 网格"区分卷积时，网格列数是按**盒尺寸**算的，跟核大小无关，**不编码任何信息却暗示了一个不存在的含义**。

我的竖线是同一个错误：条数按 `log2(通道数)` 压缩，512 通道只画 5 条，读者会以为数线就能数出通道数。契约是对的，撤掉，并补了一条测试锁住"扁平特征图内部不得有横线或竖线"。通道数本来就写在标签里（`512×28×28`）。要表达"这是摞起来的特征图"，走 3D 模式的**体量**——那是真实几何，不是装饰。

### 8.4 已知边界：单栏装不下 37 个算子

把 VGG16 压到 Cell 单栏（183 mm）后，盒宽只剩十几个单位：`MaxPool` 被迫折成两行、`Flatten` 碎成 `Flat/ten`、尺寸标注被挤出画布——`check-figure-geometry.mjs` 在这一档报出 **55 处冲突**。

**这不是渲染 bug，是物理约束。** 顶刊的 VGG16 图要么跨双栏，要么先把 `Conv+ReLU` 折叠成一个单元（37 → 16 个块）。后者正是下面清单里的「重复块折叠」。

## 九、仍然没做

**P0 解决"错误"，P1 第一批解决"物理越界与重复信息"，但版式本身还是"流程图"而不是"顶刊架构图"。**

- **连线走廊分配**：ViT 的 `Add(8) → Add(13)` 仍横穿整幅图；残差 / 跳跃线型与颜色未区分。这是下一件最该做的事。
- **重复块折叠 + `×N`**：Transformer 的"同一块重复 L 次"仍铺开成多个 `MatMul`，读不出重复结构。
- **列密度均衡**：ResNet 第 5 列只有 2 个盒子，右下方仍是大片留白；ViT 底部同理。
- **模块形状语言**：3D 模式已能画等距特征图堆（且片数随通道数，见第八节），但 `--flat` 下所有模块仍是圆角矩形。顶刊的扁平图里 VGG 用特征图板、Transformer 用矩阵条带，这一层还没做。
- **`blockKind` 粒度太粗**：ONNX 直通把 VGG16 的五个卷积段全归成 `encoder`，段带在它上面完全不可用（标签全重复 → 按规则整图退回 badge）。根因在上游，不在渲染层。
- **逐盒数字角标**：方向已正确，但"每盒一个数字"本身仍是噪声。顶刊只在正文引用步骤时才编号。
- **配色未收敛 Okabe-Ito**；**面板标签 (a)(b) 未支持**。
- `cnn-tower` 无真实样本；`lstm/gcn/gan/graphcast` 仍是 sequential 兜底；Visio 侧未同步（段带、线宽、角标规则、几何避让都还没过去）。

## 十、一句话

**字号和线宽是「印出来能不能看清」，版式是「一眼能不能读懂」。** 现在"能不能看清"全部收口，"物理越界"（溢出、压线、压盒、穿斜腰）也由独立核验器守住；**剩下的是"读起来像不像顶刊"——走廊、折叠、密度，一件都还没做。**
