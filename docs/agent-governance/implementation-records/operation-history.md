## 2026-08-21 — Core drawing-session priority shift

- **Decision:** The owner directed development to complete the general neural-network drawing Agent before continuing Visio/export infrastructure.
- **Design baseline:** `docs/superpowers/specs/2026-08-21-evidence-constrained-drawing-agent-design.md` complements the universal-agent architecture. It forbids model-name routing, source execution, raw renderer control, automatic pattern promotion, and guessed topology.
- **Implemented slice:** `EvidenceConstrainedDrawingSession` composes supported typed-prompt/static-PyTorch input into an immutable owner/device-bound UGS revision. It returns formal/candidate PVP preview only without blocking topology; otherwise it returns one deterministic clarification and no PVP. Its bounded confirmation regenerates UGS/GPG/PVP and reports semantic local delta IDs.
- **Deliberate non-goals:** no sketch understanding, provider integration, persistence, HTTP route, Snapshot, export, Worker, COM, VSDX, Visio execution, save/reopen, native readback, browser visual acceptance, or PatternLibrary promotion.
- **Ledger effect:** `M2.11` is active. `M3.2` is deferred, not abandoned; it resumes only after the core session receives independent acceptance.
- **Required evidence before acceptance:** focused Vitest, TypeScript, foundation check, strict roadmap verification, full API regression, diff check, and independent code review. Successful unit checks prove only the renderer-neutral session boundary.

## 2026-08-21 — Session hardening after independent review

- **Review outcome:** No critical defect was found, but confirmation provenance, source-digest binding, repeated clarification, and delta semantics required correction before the M2.11 slice could be considered for acceptance.
- **Hardening:** Static source hash is recomputed from submitted bytes. Candidate UGS evidence retains its real source ID and hash rather than a synthetic fallback. A session revision identity is recomputed from canonical UGS, owner/device, detail, and target. Confirmation rejects tampered source projections and target identity, then either produces the next deterministic clarification or the first PVP preview.
- **Delta contract:** Added, removed, and changed semantic PVP IDs are now mutually exclusive.
- **Evidence status:** Follow-up focused and full regression evidence is required after these changes. This log entry itself is not an acceptance claim.

## 2026-08-21 — M2.12 design-closure amendment

- **Trigger:** A second read-only architecture audit found that the receipt-bound revision had the right authority goal but still left an unusable Provider input, conflicting receipt-retention scope, an underspecified canonicalization algorithm, and a migration test that incorrectly allowed candidate PVP creation.
- **Decision:** `ProviderContextReference` is now a Coordinator-internal capability, while `ProviderContextPayload` is the only redacted object sent to a Provider. The payload contains bounded verified summaries under local fact tokens and excludes every receipt/context/run/owner/device ID, raw byte, path, credential, and public UGS ID. Provider text is a local suggestion only; Harness-owned public-text projection controls every public label and metadata field.
- **Execution order:** M2.12 is not a standalone implementation path. Its code work is gated by the master platform's Phase 0 migration inventory, Phase 1 DrawingRun state/public projection, Phase 2 Coordinator/store/idempotency/cancellation, then Phase 3 receipt/EvidencePack. The receipt-bound Harness is Phase 4 and session/route cutover is Phase 5. `owner_revision` retention belongs only to the Coordinator-owned ArtifactStore.
- **Structural rule:** The Harness canonicalizes evidence by a complete key, rejects conflicting source/locator facts, derives topology order from semantic/evidence/port/relation fingerprints, and never uses Provider local references or request-array position as an ID tie-breaker. Unresolved semantic symmetry is a clarification. Candidate, clarification, rejected, stale, or cancelled assessments create no PVP, Snapshot, export, Worker, COM, Visio, or page-binding work.
- **Ledger effect:** M2.12 remains `active` only for design/prerequisite inventory. Its `nextAction` is the Phase 0–2 prerequisite sequence; no M2.12 acceptance evidence was added and M2.13 remains `planned`.
