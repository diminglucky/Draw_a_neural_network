# Agent Operation History

This append-only operational log records a deliberate product decision separately from claims of delivery. It never substitutes for test, real-host, visual, Snapshot, export, or Git evidence.

## 2026-08-21 — Core drawing-session priority shift

- **Decision:** The owner directed development to complete the general neural-network drawing Agent before continuing Visio/export infrastructure.
- **Design baseline:** `docs/superpowers/specs/2026-08-21-evidence-constrained-drawing-agent-design.md` complements the universal-agent architecture. It forbids model-name routing, source execution, raw renderer control, automatic pattern promotion, and guessed topology.
- **Implemented slice:** `EvidenceConstrainedDrawingSession` composes supported typed-prompt/static-PyTorch input into an immutable owner/device-bound UGS revision. It returns formal/candidate PVP preview only without blocking topology; otherwise it returns one deterministic clarification and no PVP. Its bounded confirmation regenerates UGS/GPG/PVP and reports semantic local delta IDs.
- **Deliberate non-goals:** no sketch understanding, provider integration, persistence, HTTP route, Snapshot, export, Worker, COM, VSDX, Visio execution, save/reopen, native readback, browser visual acceptance, or PatternLibrary promotion.
- **Ledger effect:** `M2.11` is active. `M3.2` is deferred, not abandoned; it resumes only after the core session receives independent acceptance.
- **Required evidence before acceptance:** focused Vitest, TypeScript, foundation check, strict roadmap verification, full API regression, diff check, and independent code review. Successful unit checks prove only the renderer-neutral session boundary.

## 2026-08-21 — Session hardening after independent review

- **Review outcome:** No critical defect was found, but confirmation provenance, source-digest binding, repeated clarification, and delta semantics required correction before the M2.11 slice could be considered for acceptance.
- **Hardening:** Static source hash is recomputed from submitted bytes. Candidate UGS evidence retains its real source ID and hash rather than a synthetic fallback. A session revision identity is recomputed from canonical UGS, owner/device, detail, and target. Confirmation rejects tampered source projections and target identity, then either produces the next deterministic clarification or the first PVP preview.
- **Delta contract:** Added, removed, and changed semantic PVP IDs are now mutually exclusive.
- **Evidence status:** Follow-up focused and full regression evidence is required after these changes. This log entry itself is not an acceptance claim.

## 2026-08-21 — Core Drawing V1 vertical-slice design revision

- **Decision:** Replace the sequencing baseline with `docs/superpowers/specs/2026-08-21-core-drawing-v1-vertical-slice-design.md` and record the staged implementation route in `docs/superpowers/plans/2026-08-21-core-drawing-v1-vertical-slice.md`. The product loop is unfamiliar code/description/future sketch → bounded structural interpretation → publication-quality preview → incremental update of the current Visio page → save/reopen/readback.
- **Preserved boundaries:** UGS/GPG/PVP remain canonical; submitted source remains non-executed; a constrained interpreter may only propose evidence-referenced semantic structure; uncertainty remains a deterministic clarification; browser/model input cannot carry SVG, coordinates, COM/VBA, Worker, shell, paths, or export controls; only a sealed formal PVP may reach the Visio adapter.
- **Scope and order:** After owner review, implementation must proceed through constrained interpretation, semantic visual grammar and zero-template review, candidate-only sketch observations, and then current-document/page Visio updates that preserve unrelated user shapes. Default creation of a document, page, or canvas is disallowed.
- **Truth boundary:** This is a design and planning proposal only. It does not prove or record Provider integration, sketch understanding, visual grammar quality, current-document Visio behavior, save/reopen, native readback, real-host execution, or manual publication-visual acceptance. No ledger node changes status because of this entry.

## 2026-08-21 — Core Drawing V1 execution-contract revision

- **Trigger:** Read-only design review found that the product direction was correct but the implementation contract was insufficiently precise for long-lived updates of an already open Visio document.
- **Current-page contract:** The revised baseline requires Worker-owned discovery of existing visible targets, explicit user selection, an immutable document/page/readback/region binding, Agent-owned shape tags, pre-mutation conflict rejection, and post-mutation independent readback. The existing `OpenOrCreate` lifecycle is explicitly excluded from this path. Normal drawing leaves the user document open; explicit save/close/reopen tests run against a separately chosen target.
- **Input and quality contract:** The revision fixes the constrained architecture-interpreter schema and deterministic fallback, isolates sketch receipt/observation/candidate projection, and requires a 13-fixture semantic visual acceptance corpus with hashes plus human review. No Provider, sketch, visual grammar, current-page Visio, Worker attach, host, or visual-acceptance capability is thereby implemented.
- **Ledger effect:** None. M2.8, M2.10, and M2.11 retain their existing statuses. The revised design defines M2.12/M2.13 as future planned ledger records with explicit dependencies and acceptance contracts; it forbids activating either node or changing current focus without independently reviewed and resolvable evidence.
