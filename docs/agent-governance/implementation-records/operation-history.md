## 2026-08-26 — P0 publication-preview contract recovery

- **Observed regression:** The initial focused visual gate reported one failed file and three passed files, with 8 failed and 42 passed tests. Every anonymous SVG corpus case stopped in the browser renderer with `PVP style token is invalid`, so compiler and structural checks could pass while the generated preview remained unusable.
- **Root cause:** The canonical PVP compiler emits the unitless decimal line width `"1.2"`, while `publication-visual-plan-preview.js` accepted only integer strings from `1` through `99`. The producer and consumer therefore disagreed on a valid PVP style token.
- **Narrow repair:** The browser renderer now accepts only positive, unitless decimal line widths below `100` with at most two fractional digits. Focused contract tests cover accepted values `0.01`, `0.1`, `1`, `1.2`, `1.25`, `99`, and `99.99`, and reject zero, units, exponent notation, signs, and values at or above `100`. The PVP compiler and native Visio intent mapping were not changed.
- **Verification:** The focused RED reproduced the old rejection and the repaired targeted test passed. The complete browser-preview suite passed 22 tests. The combined compiler, anonymous corpus, structural QA, native-intent, and browser-renderer gate passed 5 files and 72 tests. `npx.cmd tsc --noEmit`, `npm.cmd run api:check`, and `git diff --check` all exited `0`; the foundation check reported its durable schema, PostgreSQL/Redis services, and explicit store factory boundary present.
- **Truth boundary:** This restores compiler-to-renderer compatibility and makes the existing corpus renderable again. It does not improve page composition, visual hierarchy, routing, semantic grouping, annotation, legend, or publication quality by itself, and it is not Visio host, save/reopen, native readback, or human visual-acceptance evidence.

## 2026-08-26 — Selected-page preflight-before-mutation safety boundary

- **Root cause:** `SelectedPageVisioComNative.ApplyOwnedRegion` deleted the existing Agent-owned namespace before `DrawSelectedPageRegion` read the real page dimensions and executed content-fit/readability validation. A deterministic fit rejection could therefore remove the last verified Agent region without producing a replacement.
- **TDD evidence:** The first RED failed compilation because `PreparedSelectedPageRegion` did not exist. Independent review then identified three bypasses; four additional RED assertions proved that missing actual page metrics silently fell back to PVP dimensions, the active selection was not re-read after preparation, the prepared token had a public constructor, and prepared drawing still accepted a raw `DiagramDocument`.
- **Implemented boundary:** The internal Worker operations contract now has explicit `PrepareOwnedRegion` and `ApplyOwnedRegion` phases. Preparation reads actual page metrics with fail-closed `NaN` fallbacks, runs the existing deterministic affine fit and readability checks, and returns an immutable target-bound token with no public constructor. The backend validates the active target before preparation, validates the prepared target, re-reads the active selection immediately before apply, and only then enters native namespace deletion/drawing/tagging. The draw helper accepts only the prepared token and does not recompute fit after deletion.
- **Compatibility:** The browser/API/Worker JSON protocol, PVP and native-intent schemas, selected-page dimensions, save behavior, and current-document lifecycle are unchanged. The operations seam and prepared token are internal to `VisioWorker.Live`; `InternalsVisibleTo` is limited to `VisioWorker.Core.Tests`.
- **Verification:** The focused selected-page backend/rendering suite passed 20 tests. The Release Worker suite passed 293 tests and skipped the two environment-gated real-Visio live-acceptance tests. `dotnet build workers/visio-worker/VisioWorker.sln -c Release --no-restore` completed with zero warnings and zero errors; `npx.cmd tsc --noEmit`, `npm.cmd run api:check`, and `git diff --check` exited `0`. An independent re-review found no remaining Critical or Important issue in this preflight slice.
- **Residual risk:** Once mutation starts, a later COM drawing, ownership-tag, source-mapping, save, or readback failure can still leave a partial or absent Agent region. This slice does not claim transactional replacement, page-aware reflow, obstacle avoidance, real-host execution, save/reopen validation, or visual acceptance. The next safety slice must use staged namespace drawing, verification, atomic promotion where Visio permits it, and bounded cleanup/recovery.
